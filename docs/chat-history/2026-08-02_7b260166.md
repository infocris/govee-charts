### 1. Commandes CLI documentées

Sources : [CLI overview](https://cursor.com/docs/cli/overview.md), [Using CLI](https://cursor.com/docs/cli/using.md), [parameters](https://cursor.com/docs/cli/reference/parameters.md).

```bash
# Lister / choisir une session CLI
agent ls

# Reprendre la dernière session CLI
agent resume
agent --continue          # alias de --resume=-1

# Reprendre une session CLI précise (chat ID issu de create-chat / ls /resume)
agent --resume="CHAT_ID"
agent --resume=CHAT_ID

# Créer une session vide et obtenir son ID (pour le figer dans un Makefile)
agent create-chat
```

Slash commandes : `/resume`, `/copy-conversation-id` ([slash commands](https://cursor.com/docs/cli/reference/slash-commands.md)).

**Pour `make agent` si la conversation est née dans le CLI :**

```makefile
AGENT_CHAT_ID ?= <id-from-agent-ls-or-create-chat>

agent:
	cd $(CURDIR) && agent --workspace $(CURDIR) --resume="$(AGENT_CHAT_ID)"
```

**Pour l’UUID IDE `bac83d87-569d-4d07-a88c-1fbed7686524` :**  
```bash
agent --resume="bac83d87-569d-4d07-a88c-1fbed7686524"
```  
n’est **pas** supporté comme bridge IDE→CLI. Staff Cursor : stores séparés (`agent-transcripts` vs `~/.cursor/chats`) ; pas d’ID stable commun ; `--resume` avec un ID IDE ne charge pas le transcript IDE et peut même l’écraser ([forum](https://forum.cursor.com/t/local-ide-agent-chats-and-the-agent-cli-still-use-separate-session-stores/165486)).

### 2. Deep links / URLs

Docs officielles [Deeplinks](https://cursor.com/docs/reference/deeplinks.md) : **prompt / command / rule uniquement** — pas de reprise de chat local.

| Type | URL | Usage |
|------|-----|--------|
| Prompt | `cursor://anysphere.cursor-deeplink/prompt?text=...` ou `https://cursor.com/link/prompt?text=...` | préremplit un **nouveau** prompt |
| Shared transcript | `https://cursor.com/s/abc123` | lecture seule (Teams/Enterprise) ; **Fork to Cursor** pour continuer ([shared transcripts](https://cursor.com/help/ai-features/shared-transcripts.md)) |
| Cloud agent | `https://cursor.com/agents/bc-<id>` | session cloud |
| Cloud deeplink | `cursor://anysphere.cursor-deeplink/background-agent?bcId=bc-<id>` | ouvre l’app (sélection d’agent parfois imperfecte) |

Rien de documenté du type `cursor://…/chat?id=bac83d87-…` pour un transcript local.

### Approche la plus proche pour `make agent`

| Objectif | Approche |
|----------|----------|
| Reprendre un chat **CLI** durable | `agent create-chat` → figer l’ID → `agent --resume="$(ID)"` |
| Rouvrir le transcript IDE `bac83d87-…` | Ouvrir Cursor sur le projet + recherche Agents (Ctrl+K) / historique ; **pas** via CLI |
| Lien partageable | Share → `cursor.com/s/…` puis Fork (Teams+) |
| Automatisation headless | SDK `Agent.resume` **après** une session SDK/CLI, pas depuis l’UUID `agent-transcripts` |

Exemple Makefile réaliste (session CLI dédiée, pas l’UUID IDE) :

```makefile
# Persist this ID after: agent create-chat  (or copy via /copy-conversation-id in CLI)
CURSOR_AGENT_CHAT_ID ?= REPLACE_WITH_CLI_CHAT_ID

.PHONY: agent agent-ls agent-new
agent:
	agent --workspace "$(CURDIR)" --resume="$(CURSOR_AGENT_CHAT_ID)"

agent-ls:
	agent ls

agent-new:
	agent create-chat
```

Pour `bac83d87-569d-4d07-a88c-1fbed7686524` : **aucune commande Makefile documentée ne restaure ce transcript IDE** ; le workflow supporté est la reprise dans l’UI, ou une **nouvelle** session CLI/SDK dont l’ID est géré explicitement.
